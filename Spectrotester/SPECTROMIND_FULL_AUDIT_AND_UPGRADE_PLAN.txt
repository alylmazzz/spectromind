1.3 Spektrum İçe Aktarma / Üretim Pipeline Yolları
-------------------------------------------------
Girdi: SMILES (textarea, satır bazlı).
  -> SpectroMasterKernel(smiles) [satır ~1883]
       - preprocessSMILES, tokenizeSMILES, parseAtomCounts, detectContext
       - detectDetailedFunctionalGroups, formulaFromSmiles (satır ~1975)
       - calculateMass, calculateDBE, partitionHydrogens
  -> generate1H(kernel, config) [satır ~3731] -> h1.signals
  -> generate13C(kernel, h1Stats, config) [satır ~5423] -> c13.signals
  -> generate2D(h1, c13, kernel, config) [satır ~7834] -> hsqc, cosy, hmbc, noesy
  -> generateMS(kernel) [satır ~7647] -> ms peaks
  -> generateIR(kernel) [satır ~7784] -> ir bands

Harici spektrum dosyası (JCAMP, MOL, CSV) okuma YOK; yalnızca kernel tarafından üretilen spektra doğrulanıyor.

2. MEVCUT YETENEKLER ÖZETİ
================================================================================

2.1 Formül ve DBE
- formulaFromSmiles kullanımı (kernel içinde); DBE hesaplanıyor; dbe_interpretation (spectral_requirements, H_C_ratio, hypotheses) runVerification içinde üretiliyor.
- Eksik: DBE parite kontrolü, DBE->spektral zorunluluk eşlemesi tam değil (kısmen veto’larda var).

2.2 1H NMR
- verify1H: integral (exclude_exchangeable), ppm penceresi, FP_RULES fingerprint, J-coupling (vicinal 6–9 Hz), çözücü notu.
- verifyMultiplicityConsistency: quartet->1×CH3, septet->2×CH3.
- Eksik: Triplet/doublet şablonları (etil, izopropil) tam kodlanmamış; dinamik ortalama/rotamer uyarıları yok; solvent baskılama modeli sadece katalog eşlemesi.

2.3 13C NMR
- verify13C: C_found vs C_expected, simetri (getC13MinExpected, getOverlapTolerance), karbonil 160–220 ppm, nitril 115–125 ppm, carbonTypes (CH3/CH2/CH/Q).
- Eksik: DEPT-135/APT işaret tahmini; relaksasyon gecikmesi hassasiyet metrikleri yok.

2.4 HSQC
- Protonlu karbon sayısı vs HSQC pik sayısı; ratio < 0.6 -> WARN; hsqcMissing için cause (low_SNR, fast_exchange, heteroatom_proton, adjacent_quaternary, electronegative_attachment) ve severity (info/warning/error).
- Eksik: Gerçek C–H bağ grafiği yok; “adjacent to quaternary” heuristik (ppm aralığı).

2.5 COSY
- all_protons_singlet -> COSY yok = VALID (PASS); anyCoupledProtons ve COSY boş -> WARN; aromatik/geminal notları.
- Eksik: Geminal çift gerçek tespiti (CH2 iki sinyal); aromatik ortho zincir doğrulaması (proton etiketleri yok).

2.6 HMBC
- Karbonil (ester/keton/amid) için 160–220 ppm H->C bekleniyor; yoksa WARN; nitril opsiyonel; invisibility_causes notları.
- Eksik: 2J vs 3J ayrı etiketleme (veri yapısında yok); fonksiyonel gruba göre “alpha proton yok” kontrolü yok.

2.7 Aromatik Sistem
- AromaticSystem substitution_patterns (mono/disub/tri/tetra); aromaticH1Integral, expectedUniqueMin/Max; pattern_match.
- Eksik: Heteroaromatik (pirin, furan) kayma aralıkları ayrı şablon değil; aromatik H vs C sayı uzlaştırması sınırlı.

2.8 MS ve FT-IR
- MS: [M+H]+/[M+Na]+/[M+K]+ eşleşmesi; ppm veto >10; Cl/Br için M+2 izotop WARN.
- IR: expectedBands (C=O, OH/NH, C≡N, Ar C=C, CH alifatik, NO2, S=O) vs foundBands; coverage; yapısal veto (C=O/OH yoksa band yasak).

A) Formül ve DBE Zekası
------------------------
Dosya: Spectromasterv0.2tester.html
- DBE hesaplama: kernel içinde calculateDBE; runVerification içinde dbeValue, dbe_interpretation.
- Eksik kurallar:
  - DBE parite (yarım tam sayı kontrolü) açık kural yok.
  - DBE=0 -> aromatik/aldehit/karbonil yasak (mevcut veto’lar var).
  - DBE hipotezleri (aromatik halka, dien, vb.) var ama “DBE -> 6–9 ppm 1H zorunluluğu” tek bir kural nesnesi değil.
- Hatalı/eksik eşik: Yok; DBE formülü standart.
- İşlenmeyen kenar: Çok azotlu/halojenli formüllerde DBE yorumu (negatif DBE kontrolü yok).

Failure Mode Örnekleri (A):
  FM-A1: DBE=3.5 girilirse (yanlış formül) sistem yine de aromatic_probability hesaplıyor; açık “DBE must be integer or half-integer” kuralı yok. Çözüm: DBE_PARITY kuralı ekle; parity fail -> INCONCLUSIVE.
  FM-A2: H/C > 2 doygun sistemde 4.5+ ppm veto var; ama H/C=1.9 sınırda “require_unsaturated_region” tetiklenebilir, eşik sabit. Çözüm: Eşiği VERIFICATION_CONFIG’e taşı (hc_ratio_saturated_threshold: 2.0).
  FM-A3: DBE=4 aromatik hipotez ağırlığı 0.7; kullanıcıya “neden aromatik bekleniyor” açıklaması root_cause’da yok. Çözüm: dbe_interpretation.hypotheses -> root_cause_analysis’e WHY metni olarak ekle.
  FM-A4: Halojen (F,Cl,Br,I) DBE formülde kullanılıyor; I sayımı bazen unutulabiliyor. Çözüm: formulaFromSmiles ve kernel.counts tutarlılık kontrolü (FORMULA_CONSISTENCY kuralı).
  FM-A5: Tautomer farklı SMILES aynı formül; teyit aynı kernel’a bağlı. Farklı tautomer için farklı fingerprint beklenebilir. Çözüm: tautomer_key provenance’da var; FP_RULES’ta tautomer alternatifleri tanımlanabilir.

B) 1H NMR
---------
Dosya: Spectromasterv0.2tester.html – verify1H (~15298), verifyMultiplicityConsistency (~15479), runVerification içi veto’lar.
- Eksik kurallar:
  - Triplet + komşu CH2 sayısı (etil şablonu): kodda “quartet/septet” var; “triplet 2H + quartet 3H” etil şablonu yok.
  - Doublet + komşu 1H (izopropil): septet için 2×CH3 var; “doublet 6H + septet 1H” açık şablon yok.
  - Değişebilir proton: integral hariç tutuluyor; D2O değişim sonrası “kaybolan” sinyal için ayrı bayrak yok.
  - Dinamik ortalama: amid rotamer, engelli rotasyon uyarısı yok.
  - Solvent: sadece katalog eşlemesi; “su baskılama” ile eksik integral açıklaması yok.
- Yanlış eşik: integral_tolerance_ratio 0.2 (0.15 de kullanılıyor); tek yerde sabit. Değişebilir H için tolerans ayrı olmalı.
- Kenar: Lokal ondalık ayırıcı (virgül) integral parse’da kabul edilmiyor (parseInteg sadece nokta).

Failure Mode Örnekleri (B):
  FM-B1: Etil asetat 3H t + 2H q üretir; multiplicity doğru ama “etil şablonu (t+q) integral 5H” kuralı yok; yanlışlıkla 4H+3H verilirse integral 7 kalır, FAIL. Çözüm: ETHYL_TEMPLATE kuralı (triplet 3H, quartet 2H, toplam 5H).
  FM-B2: t-BuOH sadece 9H s; COSY boş. Mevcut kod “all singlets -> COSY valid” diyor (doğru). Ama UI’da “COSY missing” diye yanlış yorumlanabilir. Çözüm: COSY_EXPECTATION çıktısını UI’da “COSY beklenmiyor (tüm singlet)” olarak göstermek.
  FM-B3: Fenol OH geniş; integral 1 sayılmayabilir (baseline). exclude_exchangeable=true ile 5H beklenir; 5.2H bulunursa tol içinde. Ama “5.0” yerine “5” yazılmazsa parseInteg “5” verir. Çözüm: Ondalık ve virgül parse (locale) + exchangeable_integral_tolerance_ratio ayrı.
  FM-B4: Piridin 5H aromatik; multiplet “m” olabilir. Fingerprint “5H 7.1-8.8” arıyor; bölge sayımı doğru. Ama FP_RULES’ta piridin SMILES (n1ccccc1) farklı yazılmışsa eşleşmez. Çözüm: FP_ALT_KEYS veya normalizasyon ile n1ccccc1 / pyridine eşlemesi.
  FM-B5: Çok dar multiplet “s” gibi raporlanabilir; J küçük. verifyMultiplicityConsistency “septet -> 2 CH3” arıyor; “s” için sessiz geçiyor. Yanlış “s” atanırsa COSY beklentisi düşer (iyi); ama “d” olması gerekirken “s” kabul edilirse yanlış negatif. Çözüm: Multiplicity refinement kuralı (J>0 ise en az d/t/q beklenir).

C) 13C NMR
----------
Dosya: Spectromasterv0.2tester.html – verify13C (~14594), clusterC13 (~14517), runVerification c13 modülü.
- Eksik kurallar:
  - Karbon sınıf dağılımı (CH3/CH2/CH/Q) yapıdan türetilmiyor; sadece gözlenen typeCounts.
  - DEPT-135 pozitif/negatif tahmini yok.
  - Relaksasyon gecikmesi (d1) ile kuaterner eksikliği “relaxation_risk” notu var; eşik yok.
  - Aromatik karbon örtüşmesi (110–160 ppm) “observed_aromatic_signals” var; “beklenen benzersiz aromatik C” yapıdan türetilmiyor.
- Eşik: c13_delta_pass_max_pct: 30; overlapTol (getOverlapTolerance) C<=10 %100, C<=20 %80, C>20 %60. Sabit.
- Kenar: TFA gibi CF3COO; 13C’de CH yok. VETO_C13_TFA_ALIPHATIC var; iyi.

Failure Mode Örnekleri (C):
  FM-C1: Simetrik molekül (benzen) 6 C, 1 sinyal; C_expected_revised SymmetryDetector ile düşebilir. SymmetryDetector yoksa C_expected=6 kalır, C_found=1 -> FAIL. Çözüm: SymmetryDetector zorunlu; yoksa fallback expected_unique_carbons = ceil(C/2) gibi.
  FM-C2: Karbonil 165 ppm; nitril 119 ppm. Bölge kontrolü 160–220 ve 115–125. 155 ppm’de pik (yanlış atama) veto’ya takılmaz; “carbonyl bölgesi” dışında. Çözüm: “Yapıda karbonil var, 160–220 dışında C=O ataması yasak” kuralı (C13_NO_CARBONYL_OUTSIDE_RANGE).
  FM-C3: DEPT verisi yok; type CH/Q ataması üreticiden geliyor. Teyit “gözlenen type” ile yapıyı karşılaştıramıyor. Çözüm: Yapıdan beklenen CH3/CH2/CH sayısı (graph) + C13_CLASS_DISTRIBUTION kuralı.
  FM-C4: Uzun relaksasyon gecikmesi olmayan 13C’de kuaterner eksik; c13_relaxation_risk WARN. Ama “d1 < 2s” bilgisi yok. Çözüm: metadata’da d1 varsa “d1 < 2s and Cq missing -> WARN, suggest increase d1”.
  FM-C5: Çok sayıda C (C>20) overlapTol 0.6; C_found/C_expected >= 0.6 kabul. C_expected=24, C_found=14 -> 14/24<0.6 -> FAIL. Doğru; ama simetri ile 24’ün 12’si benzersiz olabilir. Çözüm: Simetri ile C_min revize (zaten var); C_min=12 ise 14>=12 WARN yapılmalı.

D) HSQC
-------
Dosya: Spectromasterv0.2tester.html – runVerification içi HSQC bloğu (~15781), NMR_ANALYSIS_RULES.HSQC.
- Eksik: Gerçek “bu karbon protonlu mu” grafi yok; protonatedCarbons c13Signals’dan type CH/CH2/CH3 ile alınıyor. Exchangeable eşlemesi “nearExch” ile ppm yakınlığı (cppm/50 kabaca); bilimsel olarak OH’ın C’ye bağlı olmaması gerekir.
- Mevcut: cause (fast_exchange, adjacent_quaternary, electronegative_attachment), severity (info/warning/error) iyi.
- Kenar: Aldehit CHO 1J ~175 Hz; standart HSQC optimizasyonu dışında kalabilir. “electronegative_attachment” 9.3–10.5 ppm ile yakalanıyor.

Failure Mode Örnekleri (D):
  FM-D1: OH protonu 4.5 ppm’de; yakın C 60 ppm yok; “nearExch” (cppm/50 ~ 1.2) ile eşleşmez. cause yine “fast_exchange” (exchH>0 ve possibleHAll.some(isExchangeableH)) atanıyor. İyi.
  FM-D2: Karbonil α-CH 45 ppm; hasCarbonylForAdjacent && cppm 20–55 -> adjacent_quaternary. HSQC eksikse severity warning. Doğru.
  FM-D3: Tek protonlu karbon (CH) HSQC’de yok; cause low_SNR; severity error. Ama gerçekte exchangeable ise info olmalı. Exchangeable tespiti sadece 1H mult/assign ile; 13C tarafında “O/N bağlı C” bilgisi yok. Çözüm: Yapıdan “O/N-adjacent C” listesi; bu C’ler için missing HSQC -> severity downgrade.
  FM-D4: Rapor çıktısında severity_grading var; UI’da “Eksik: C 45 ppm (CH) – … [Şiddet: warning]” gösteriliyor. Açıklama yeterli.
  FM-D5: C_protonated=0 (tüm C quaternary) ise hsqcFound=0 PASS. Mevcut kod C_protonated>0 kontrolü yapıyor; 0 ise ratio hesaplanmıyor, hsqcStatus PASS. Doğru.

E) COSY
-------
Dosya: Spectromasterv0.2tester.html – COSY bloğu (~15863), NMR_ANALYSIS_RULES.COSY.
- Eksik: Geminal çift gerçek tespiti (aynı karbonda iki H); proton etiketleri olmadığı için “mutual coupling” bilinmiyor. Aromatik ortho zincir (H2–H3–H4–H5–H6) doğrulaması için proton–proton eşlemesi yok.
- Mevcut: all_protons_singlet -> VALID; anyCoupledProtons ve cosyFound=0 -> WARN. COSY_EXPECTATION, geminal_coupling notu, aromatic_patterns notu.

Failure Mode Örnekleri (E):
  FM-E1: t-BuOH: tüm singlet, COSY 0. Kod “COSY_EXPECTATION: Tüm protonlar singlet – çapraz pik beklenmez (geçerli)”. False positive yok. İyi.
  FM-E2: Toluen: 5H m, 3H s. anyCoupledProtons “m” ile true. COSY üretimde toluen için cosy var mı? generate2D’de aromatik H–H korelasyonu üretiliyorsa cosyFound>0. Yoksa WARN. Bu beklenen; yanlış uyarı değil.
  FM-E3: Etil grubu t+q; COSY’de CH3–CH2 korelasyonu beklenir. Mevcut kod “expected cross-peak” sayısını proton çiftlerinden hesaplamıyor. Çözüm: COSY_EXPECTED_PAIRS (vicinal çiftler) yapıdan veya multiplicity’den türet; eksik çift sayısına göre severity.
  FM-E4: Para-disubstituted benzen 4H, 2 set doublet. “para_disubstituted_sym” pattern; expected_COSY “two ortho pairs”. Kod sadece not ekliyor; “2 ortho çifti var mı” sayısal kontrol yok. Çözüm: Aromatik H sayısı 4 ve 2 benzersiz ppm seti -> en az 1 COSY çifti beklenir.
  FM-E5: Metil eter (CH3-O-CH3) 6H s; COSY 0. VALID. Doğru.

F) HMBC
-------
Dosya: Spectromasterv0.2tester.html – HMBC bloğu (~15908), NMR_ANALYSIS_RULES.HMBC.
- Eksik: 2J vs 3J etiketleme (corr.hmbc nesnelerinde bondOrder veya distance yok); “alpha proton yok” (yapıda C=O yanında H yok) kontrolü yok, bu durumda HMBC beklenmemeli.
- Mevcut: hasRequiredCarbonyl && hmbcToCarbonyl.length===0 -> WARN; nitrile optional; invisibility_causes metni.

Failure Mode Örnekleri (F):
  FM-F1: Aseton (CH3)2C=O; karbonil yanında H yok (kuaterner). HMBC’de H->C=O 3J ile mümkün (metil->C=O). Mevcut “hasRequiredCarbonyl” true; hmbcToCarbonyl beklenir. Üretici HMBC üretiyorsa bulunur. Doğru.
  FM-F2: TFA CF3C(=O)OH; karbonil α’da F, proton yok. 2J/3J HMBC olmaz. Kod “hasRequiredCarbonyl” (ester+ketone+amide) -> acid de var mı? groups.acid > 0. O zaman yine WARN verir. Hata: asit için α-H yoksa HMBC opsiyonel olmalı. Çözüm: HMBC functional_group_rules’ta acid_C=O: expected_correlation: true only_if_alpha_H.
  FM-F3: Nitril: hasOptionalNitrile && hmbcFound===0 -> sadece not, WARN yok. Doğru.
  FM-F4: Ester C=O, α-CH3 var; HMBC 160–220 bölgesinde yok. WARN + “2J (α-proton) öncelikli”. Kullanıcı “neden 2J” görür. İyi.
  FM-F5: “No proton within 3 bonds” – kod bunu yapıdan hesaplamıyor; sadece invisibility_causes listesinde metin. Çözüm: Karbon bazlı “twoBondProtons, threeBondProtons” (yapıdan) eklenirse, 0 ise HMBC optional.

G) Aromatik Sistem ve MS/IR
----------------------------
- Aromatik: substitution_patterns, aromaticH1Integral, inferredPattern; heteroaromatik ayrı shift aralığı yok (pirin 7–8.5, furan daha düşük).
- MS: Halojen M+2; S için M+2 oranı kuralı yok (sadece Cl/Br).
- IR: C=O, OH/NH, C≡N, NO2, S=O bantları; konsantrasyon/yol uzunluğu “soft” notu var.

Failure Mode Örnekleri (G):
  FM-G1: Furan 4H; aromatik bölge 6–7.5 ppm. Mevcut aromatic_ppm_range_1h [6,9]; furan uyuyor. Furan FP_RULES’ta “6.0–7.7 bandında 4H”. İyi.
  FM-G2: Sülfür (S) içeren molekül; MS M+2 (32S->34S) zayıf. isotope_rules’ta S yok. Çözüm: isotope_rules.S: M2_ratio_min/max (opsiyonel).
  FM-G3: UI’da “STRONG-VALIDATED” modules.h1?.score>=95 ile; score 70 (WARN) ise “VALIDATED”. Kullanıcı WARN’ı “geçti” sanabilir. Çözüm: Etiket “WARN ile geçti” ayrı gösterilmeli.

function evaluateRule(rule: RuleDef, context: VerificationContext): RuleResult {
  const { kernel, h1, c13, ms, ir, corr } = context;
  // rule.prerequisites kontrolü
  // rule mantığı; evidence toplama
  return { rule_id: rule.rule_id, status: "PASS", severity: 0, message: "", evidence: {}, why_narrative: "", suggested_action: "" };
}

function evaluateAll(ruleset: RuleDef[], context: VerificationContext): Scorecard {
  const results = ruleset.map(r => evaluateRule(r, context));
  const totalWeight = results.reduce((s, r) => s + severityWeight(r.status), 0);
  const score = Math.max(0, 100 - totalWeight);
  const veto = results.some(r => r.status === "FATAL" || r.status === "ERROR");
  return { results, score, veto, pass: !veto && results.every(r => r.status !== "ERROR") };
}

6.4 Şiddet ve Skorlama
-----------------------
const SEVERITY_WEIGHT = { PASS: 0, INFO: 1, WARN: 2, ERROR: 5, FATAL: 10 };
function severityWeight(status: string): number { return SEVERITY_WEIGHT[status] ?? 0; }
// PASS with WARN: score 70–99; FAIL: veto_flags.length>0 veya ERROR; FATAL: kesin red.

6.5 Açıklanabilirlik
---------------------
function renderNarrative(ruleResults: RuleResult[]): string {
  const failed = ruleResults.filter(r => r.status !== "PASS");
  return failed.map(r => `${r.rule_id}: ${r.why_narrative} Öneri: ${r.suggested_action}`).join("\n");
}

  - degree(atomId), isHetero(atomId), isCarbonylCarbon(atomId), isNitrileCarbon(atomId)
  - alphaProtonsOfCarbonyl(carbonId), pathDistance(a, b)

Türetilecek çıktılar (graf veya kernel fallback ile):
  - expectedProtonatedCarbons: CH/CH2/CH3 listesi (yapıdan)
  - expectedHCountNonExchangeable, expectedExchangeableHCount
  - expectedEthyl / expectedIsopropyl / expectedTertButyl: motif dedektörleri
  - expectedCOSYPairs: vicinal (3J) çiftleri (H-bearing atomlar arası)
  - expectedHMBCPairs: 2J/3J H→C hedefleri (özellikle C=O, CN)
  - expectedAromaticPattern: mono/ortho/meta/para (halka substituent pozisyonları)

Uygulama: Spectromasterv0.2tester.html içinde buildMoleculeGraphFromKernel(kernel, c13Signals)
          ile kernel + typeCounts kullanarak beklenti listeleri doldurulur; tam SMILES→graf
          için harici parser (örn. openchemlib) veya lib/ içi modül sonra eklenebilir.

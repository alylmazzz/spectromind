1. PROJE GENEL BAKIŞ
═══════════════════════════════════════════════════════════════════════════════

SpectroMind, NMR spektroskopi verilerinden moleküler yapı belirleme için 
AI destekli bir platformdur. Next.js 16 tabanlı, TypeScript ile geliştirilmiş,
Python RDKit entegrasyonlu hibrit bir mimariye sahiptir.

ANA ÖZELLİKLER:
- 1H NMR, 13C NMR, FTIR ve MS (Kütle Spektrometrisi) spektrum analizi
- PubChem (966M+ molekül) entegrasyonu
- AI destekli yapı tahmini (Gemini/OpenAI)
- RDKit v1.5 7-engine elucidation pipeline
- Enhanced Library (794+ analiz edilmiş molekül cache)
- Teorik spektrum enhancement (10 modül)
- FID dosya işleme (Client-Side WebAssembly)
- 2D/3D molekül görselleştirme
- v2.0 YENİ MODÜLLER:
  * MS (Mass Spectrometry) Tahmin Modülü
  * 3D Konformer Üretimi ve Boltzmann Ağırlıklandırma
  * Kuantum Mekaniksel (QM/DFT) Doğrulama Katmanı
  * Vektör Tabanlı Benzerlik Arama (RAG)
  * Client-Side FID İşleme (Pyodide)

TEKNOLOJİ STACK:
- Frontend: Next.js 16, React 19, TypeScript 5
- Backend: Next.js API Routes (Node.js)
- NMR Engine: Python 3.14, RDKit
- AI: Google Gemini API, OpenAI GPT-4O
- Database: JSON files (Enhanced Library, Analysis History)
- External APIs: PubChem REST API, Crossref API, NMRShiftDB2
- Visualization: Chart.js, 3DMol.js, RDKit
- v2.0 YENİ TEKNOLOJİLER:
  * Pyodide (Python in WebAssembly) - Client-side processing
  * ASE (Atomic Simulation Environment) - QM calculations
  * xTB (Semi-empirical QM) - DFT verification
  * Sentence Transformers - Vector embeddings
  * NumPy/SciPy (WASM) - Signal processing

4.1. API ROUTES (Next.js App Router)

API Route Yapısı:
/app/api/[route-name]/route.ts

ÖNEMLİ API ROUTES:

1. /api/ai-nmr-predict (route.ts - 777 satır)
   - AI ile NMR spektrum tahmini
   - Input: moleculeName, SMILES, InChI, formula, literature
   - Process:
     * Crossref'den abstract çekme
     * Fonksiyonel grup kütüphanesi entegrasyonu
     * Silverstein metodolojisi
     * GPT-4O ile tahmin
     * J değerleri ve kompleks multiplicities
     * Retry mekanizması (5+ atom farkı varsa)
   - Output: AI predicted peaks with coupling constants

2. /api/pubchem (route.ts)
   - PubChem REST API proxy
   - Endpoints:
     * /api/pubchem?type=name&query=aspirin
     * /api/pubchem?type=formula&query=C9H8O4
     * /api/pubchem/search-by-peaks (POST)
   - Returns: { name, formula, cid, synonyms, iupacName }

3. /api/pubchem/iupac (route.ts)
   - IUPAC name ve molecular formula çekme
   - Formula validation
   - Mismatch detection

4. /api/enhanced-library (route.ts)
   - AI cache yönetimi
   - GET: Kütüphaneyi yükle
   - POST: Yeni analiz ekle
   - Version: 2.0.0 (solvent/frequency aware)

5. /api/elucidation-v15 (route.ts)
   - RDKit Python pipeline çağrısı
   - Subprocess spawn: elucidation_v15.py
   - 7-engine pipeline koordinasyonu

6. /api/hose-predict (route.ts)
   - HOSE code based prediction
   - RDKit HOSE code generation
   - Theoretical shift prediction

7. /api/ftir-predict (route.ts)
   - FTIR spektrum tahmini
   - SMILES → IR peaks
   - Normal mode calculation

8. /api/fid/process (route.ts)
   - FID dosya işleme
   - Python fid_processor.py çağrısı
   - FFT → NMR spectrum

6. ALGORİTMALAR VE FORMÜLLER
═══════════════════════════════════════════════════════════════════════════════

6.1. PEAK VALIDATION ALGORİTMALARI

6.1.1. Chemical Shift Validation

1H NMR Shift Range:
  Normal: 0-15 ppm
  Extended: -2 to 18 ppm
  Very downfield (>15): Enolic OH, COOH

13C NMR Shift Range:
  Normal: 0-220 ppm
  Extended: -10 to 250 ppm
  Very downfield (>220): Rare for organic compounds

FTIR Wavenumber Range:
  Typical: 400-4000 cm⁻¹
  Below 400: Far-IR (rare)
  Above 4000: Overtones (weak)

6.1.2. Integration Normalization (Silverstein Method)

Algorithm:
  1. Find smallest integration value: min_integ
  2. Divide all by min_integ → ratios
  3. Multiply by 2, 3, 4... until whole numbers
  4. Verify total H matches molecular formula

Example:
  Raw: 1.76 : 2.64 : 1.77 : 2.59
  Step 1: min = 1.76
  Step 2: 1.0 : 1.5 : 1.01 : 1.47
  Step 3: ×2 → 2 : 3 : 2 : 3
  Step 4: Total = 10H ✓

6.1.3. Multiplicity Validation

n+1 Rule:
  Multiplicity = n + 1
  n = number of equivalent neighboring protons

Examples:
  s (singlet): n = 0, no neighbors
  d (doublet): n = 1, one neighbor
  t (triplet): n = 2, two equivalent neighbors
  q (quartet): n = 3, three equivalent neighbors
  dd (doublet of doublets): n = 2 (different neighbors)
  m (multiplet): complex, n > 3 or non-equivalent

6.1.4. Coupling Constant (J Value) Validation

Expected J Count by Multiplicity:
  s: 0 J values
  d: 1 J value
  t: 1 J value
  q: 1 J value
  dd: 2 J values
  dt: 2 J values
  td: 2 J values
  ddd: 3 J values
  m: variable

Typical J Value Ranges:
  ³J (vicinal, aliphatic): 6-8 Hz
  ³J (aromatic ortho): 7-10 Hz
  ³J (vinyl trans): 11-18 Hz
  ³J (vinyl cis): 6-15 Hz
  ²J (geminal, CH₂): 10-15 Hz
  ⁴J (aromatic meta): 2-3 Hz
  ⁴J (allylic): 1-3 Hz
  ⁵J (aromatic para): 0-1 Hz

6.2. KARPLUS EQUATION (J-Coupling Calculation)

Formula:
  J = A·cos²(θ) + B·cos(θ) + C

Where:
  θ = dihedral angle (degrees)
  A, B, C = constants (molecule-dependent)

Typical Values:
  A = 7.0 Hz
  B = -1.0 Hz
  C = 5.0 Hz

Dihedral Angle Effects:
  θ = 0° or 180° → J ≈ 8-12 Hz (maximum)
  θ = 90° → J ≈ 0-2 Hz (minimum, may appear as singlet)
  θ = 60° → J ≈ 4-6 Hz (intermediate)

Implementation (theoreticalSpectrum.ts):
  calculateDihedralAngle(atom1, atom2, atom3, atom4)
  J = A * Math.cos(θ)² + B * Math.cos(θ) + C

6.3. BOLTZMANN WEIGHTING (Module 1)

Formula:
  w_i = exp(-E_i / RT) / Σ exp(-E_j / RT)

Where:
  w_i = weight of conformer i
  E_i = energy of conformer i (kcal/mol)
  R = 8.314 J/(mol·K) = 1.987 cal/(mol·K)
  T = temperature (K, default 298.15)

Implementation:
  function calculateBoltzmannWeights(conformers, temperature):
    energies = conformers.map(c => c.energy)
    min_energy = Math.min(...energies)
    exp_values = energies.map(e => Math.exp(-(e - min_energy) / (R * T / 1000)))
    sum_exp = exp_values.reduce((a, b) => a + b, 0)
    weights = exp_values.map(exp => exp / sum_exp)
    return weights

6.4. NMR TIMESCALE EXCHANGE (Module 2)

Fast Exchange:
  k_exchange >> Δν (Hz)
  → Single averaged peak
  → Chemical shift = weighted average

Slow Exchange:
  k_exchange << Δν (Hz)
  → Separate peaks
  → Original chemical shifts

Intermediate Exchange:
  k_exchange ≈ Δν (Hz)
  → Broadened peaks
  → Coalescence temperature

Exchange Rate Calculation:
  k = (π * Δν_coalescence) / √2

Where:
  k = exchange rate constant
  Δν_coalescence = frequency difference at coalescence

6.5. INTEGRATION MATCHING ALGORİTMASI

Algorithm:
  1. Calculate total integration from peaks
  2. Extract total hydrogens from molecular formula
  3. Compare: |totalIntegration - totalHydrogens|
  4. IF difference ≥ 5 atoms:
     → TRIGGER RETRY with enhanced prompt
  5. Calculate ratio: totalIntegration / totalHydrogens
  6. IF ratio < 0.5 OR ratio > 2.0:
     → ERROR: Major mismatch
  7. IF |ratio - 1.0| > 0.1:
     → WARNING: Minor mismatch

6.6. PEAK MATCHING ALGORİTMASI (Enhanced Library)

Algorithm:
  1. FOR each library entry:
     a. FOR each library peak:
        - Calculate distance: |user_shift - lib_shift|
        - IF distance ≤ tolerance (0.1 ppm):
           → MATCH
     b. Count matches
     c. Calculate similarity: matches / max(user_peaks, lib_peaks)
  2. IF similarity ≥ 0.95:
     → RETURN library result (INSTANT)
  3. ELSE:
     → Continue to PubChem search

6.7. FORMULA PARSING ALGORİTMASI

Algorithm:
  Input: "C47H51NO14"
  
  1. Match pattern: /([A-Z][a-z]?)(\d*)/g
  2. Extract: C47, H51, N1, O14
  3. Parse numbers:
     - C: 47
     - H: 51
     - N: 1 (implicit 1)
     - O: 14
  4. Calculate:
     - totalCarbons = 47
     - totalHydrogens = 51
     - totalNitrogens = 1
     - totalOxygens = 14

6.8. DBE (Degree of Unsaturation) CALCULATION

Formula:
  DBE = C - (H/2) + (N/2) + 1

Where:
  C = number of carbons
  H = number of hydrogens
  N = number of nitrogens
  (Halogens count as H)

Interpretation:
  DBE = 0 → Saturated (only C-C, C-H single bonds)
  DBE = 1 → One unsaturation (C=O, C=C, or ring)
  DBE = 4 → Aromatic ring (benzene)
  DBE ≥ 7 → Multiple aromatic rings or complex structures

6.9. HOSE CODE PREDICTION

Algorithm:
  1. Generate HOSE code from SMILES (RDKit)
  2. Match HOSE code in database
  3. Retrieve experimental shifts
  4. Calculate weighted average
  5. Return predicted shift ± confidence

HOSE Code Format:
  [Atom][Neighbor1][Neighbor2][Neighbor3]...

Example:
  C[CH3][CH3][CH3] → Tertiary carbon with 3 CH3 neighbors

6.10. FTIR NORMAL MODE CALCULATION

Algorithm:
  1. Parse SMILES → Molecular graph
  2. Assign hybridization (sp, sp², sp³)
  3. Detect symmetry groups
  4. Calculate force constants:
     - C-H stretch: ~3000 cm⁻¹
     - C=O stretch: ~1700 cm⁻¹
     - C-O stretch: ~1200 cm⁻¹
  5. Solve normal mode equations
  6. Return: { wavenumber, intensity, assignment }

9.9.1.1. Robust JSON Parsing and Error Handling

Problem:
  LLM responses may contain malformed JSON, especially with:
  - Long SMILES strings (2000+ characters)
  - Unescaped special characters
  - URL-encoded characters
  - Unterminated strings
  - Control characters
  - Markdown code blocks

Solution: Multi-Stage JSON Cleaning Pipeline

Stage 1: Markdown Code Block Extraction
  - Pattern: /```(?:json)?\s*(\{[\s\S]*\})\s*```/
  - Extract JSON from markdown if present
  - Remove surrounding markdown syntax

Stage 2: BOM (Byte Order Mark) Removal
  - Check first character: charCodeAt(0) === 0xFEFF
  - Remove BOM if present

Stage 3: Control Character Removal
  - Remove: /[\u0000-\u001F\u007F-\u009F]/g
  - Preserve escaped sequences (\n, \t, \r)

Stage 4: SMILES String Special Handling
  - Pattern: /"smiles"\s*:\s*"(.*?)"/g
  - Decode URL-encoded parts: decodeURIComponent()
  - Escape unescaped quotes and backslashes
  - Handle very long SMILES (up to 2000 characters)

Stage 5: String Termination Fixes
  - Fix unescaped quotes within string values
  - Close unclosed objects/arrays at the end
  - Balance braces and brackets

Stage 6: Trailing Comma Removal
  - Remove: /,\s*\}/g and /,\s*\]/g
  - Fix trailing commas before closing braces/brackets

Fallback Strategies:

Fallback 1: Aggressive Cleaning
  - Apply all cleaning steps again
  - Extract JSON substring between first '{' and last '}'
  - Remove newlines within string values

Fallback 2: Regex-Based Field Extraction
  - Extract key fields manually:
    * moleculeName: /"moleculeName"\s*:\s*"(.*?)(?<!\\)"/
    * formula: /"formula"\s*:\s*"(.*?)(?<!\\)"/
    * smiles: /"smiles"\s*:\s*"(.*?)(?<!\\)"/
    * confidence: /"confidence"\s*:\s*(\d+)/
    * reasoning: /"reasoning"\s*:\s*"(.*?)(?<!\\)"/
  - Construct partial result object
  - Log warning for partial parse

SMILES Validation:
  - Valid characters: /^[A-Za-z0-9@\[\]\(\)=#\-\+\.\\/\\:]+$/
  - Length: 2-2000 characters
  - Bracket balance: [ ] and ( ) must match
  - If invalid: Set smiles to undefined, log warning

Error Handling:
  - All errors logged with full context
  - Original response text preserved for debugging
  - User-friendly error messages returned
  - Never expose internal errors to client

Performance:
  - Parsing typically < 10ms
  - Fallback strategies add < 50ms
  - No performance impact on successful parses

     - Positive number check
     - >100 warning (normalizasyon önerisi)
  3. Multiplicity Validation
     - Expected coupling count check
     - n+1 rule validation
  4. J Value Validation
     - Multiplicity'ye göre J sayısı kontrolü
     - J değeri aralıkları (vicinal, geminal, long-range)

13.2.2. Peak Matching Algoritması

Enhanced Library Search:
  Algorithm:
    1. Peak hash oluşturma:
       - Peak'leri shift'e göre sırala
       - Format: "shift_mult_integ|shift_mult_integ|..."
       - Base64 encoding
    2. Hash matching:
       - Exact match: inputHash === libraryHash
       - Koşul kontrolü: solvent, frequency, spectrumType
    3. Similarity calculation:
       - Peak-by-peak matching (±0.1 ppm tolerance)
       - Similarity = matches / max(user_peaks, lib_peaks)
    4. Threshold: ≥95% → INSTANT result

13.2.3. Integration Normalization (Silverstein Method)

Algorithm:
  1. Find smallest integration: min_integ
  2. Normalize: ratios = peaks.map(p => p.integ / min_integ)
  3. Multiply by integer: ×2, ×3, ×4... until whole numbers
  4. Verify: totalIntegration === totalHydrogens (from formula)

Example:
  Raw: [1.76, 2.64, 1.77, 2.59]
  Step 1: min = 1.76
  Step 2: [1.0, 1.5, 1.01, 1.47]
  Step 3: ×2 → [2, 3, 2, 3]
  Step 4: Total = 10H ✓

13.2.4. Multiplicity Analysis

n+1 Rule Implementation:
  - s (singlet): n = 0 neighbors
  - d (doublet): n = 1 neighbor
  - t (triplet): n = 2 equivalent neighbors
  - q (quartet): n = 3 equivalent neighbors
  - dd (doublet of doublets): n = 2 (different neighbors)
  - m (multiplet): n > 3 or non-equivalent

Expected Coupling Count:
  - s: 0 J values
  - d, t, q: 1 J value
  - dd, dt, td: 2 J values
  - ddd: 3 J values
  - m: variable

13.3. FTIR VALİDASYON SİSTEMİ

13.3.1. Aldehyde C-H Doublet Detection

Function: detectAldehydeCHDoublet(peaks, hasCarbonyl)

Critical Feature:
  - 2750 cm⁻¹ band: VIRTUALLY UNIQUE to aldehydes!
  - 2860-2800 cm⁻¹: weak (often obscured)
  - 2760-2700 cm⁻¹: DIAGNOSTIC!

Algorithm:
  1. Find peaks in regions:
     - High: 2800-2860 cm⁻¹
     - Low: 2700-2760 cm⁻¹ (CRITICAL!)
  2. Confidence calculation:
     - High: Low band + C=O present
     - Medium: Low band only
     - Low: High band only

13.3.2. Carboxylic Acid Detection

Function: detectCarboxylicAcid(hasBroadOH, carbonylPeak, hasCOStretch)

Features:
  - Super-broad O-H: 2400-3400 cm⁻¹ (1000 cm⁻¹ width!)
  - Dimer C=O: ~1710 cm⁻¹
  - C-O stretch: ~1260 cm⁻¹

Algorithm:
  1. Check broad O-H absorption (2400-3400 cm⁻¹)
  2. Check C=O position:
     - Dimer: 1700-1720 cm⁻¹
     - Monomer: 1750-1770 cm⁻¹
  3. Check C-O stretch (1260 cm⁻¹)
  4. Confidence:
     - High: All features present
     - Medium: Broad O-H + C=O

13.3.3. Amide Type Classification

Function: classifyAmideType(nhBandCount, carbonylPeak, hasNHBend)

Types:
  - Primary (R-CONH₂): 2 N-H bands (3350 + 3180 cm⁻¹)
  - Secondary (R-CONHR): 1 N-H band (~3300 cm⁻¹)
  - Tertiary (R-CONR₂): 0 N-H bands

Algorithm:
  1. Count N-H bands in 3500-3000 cm⁻¹
  2. Check C=O position (1630-1700 cm⁻¹)
  3. Check N-H bend (1640-1550 cm⁻¹)
  4. Classify based on band count

13.3.4. Anhydride Doublet Detection

Function: detectAnhydrideDoublet(peaks)

Critical Feature:
  - ALWAYS shows TWO C=O bands!
  - Asymmetric: 1830-1800 cm⁻¹
  - Symmetric: 1775-1740 cm⁻¹

Algorithm:
  1. Find asymmetric C=O (1800-1860 cm⁻¹)
  2. Find symmetric C=O (1740-1790 cm⁻¹)
  3. Both present → HIGH confidence
  4. Type detection:
     - Cyclic: asymmetric > 1840 cm⁻¹ (ring strain)
     - Aliphatic: normal range

13.3.5. Nitro Compound Detection

Function: detectNitroDoublet(peaks, isAromatic)

Features:
  - Aliphatic: 1600-1530 cm⁻¹ (asym) + 1390-1300 cm⁻¹ (sym)
  - Aromatic: 1550-1490 cm⁻¹ (asym) + 1355-1315 cm⁻¹ (sym)
  - Aromatic: TWO bands of EQUAL intensity!

13.3.6. Triple Bond Differentiation

Function: classifyTripleBond(peaks, hasTerminalCH, peakIntensity)

Types:
  - Nitrile (R-C≡N): 2270-2210 cm⁻¹, medium, sharp, NO 3300 cm⁻¹
  - Alkyne (R-C≡C-H): ~3300 cm⁻¹ (≡C-H) + ~2150 cm⁻¹ (C≡C)
  - Isocyanate (R-N=C=O): ~2270 cm⁻¹, VERY INTENSE, broad

Algorithm:
  1. Check for 3300 cm⁻¹ (≡C-H)
  2. Check for 2150 cm⁻¹ (C≡C)
  3. Check intensity at 2200 cm⁻¹
  4. Classify based on pattern

13.3.7. Ester C-O Pattern Detection

Function: detectEsterCOPattern(carbonylPeak, hasStrongCO, hasWeakCO)

Features:
  - C=O: 1750-1735 cm⁻¹
  - Strong C-O: 1300-1150 cm⁻¹ (acid side)
  - Weak C-O: 1150-1000 cm⁻¹ (alcohol side)

13.3.8. β-Diketone Tautomer Detection

Function: detectDiketoneTautomers(peaks, hasBroadOH)

Forms:
  - Keto: TWO C=O bands (1723 + 1706 cm⁻¹)
  - Enol: Lowered C=O (1622 cm⁻¹) + broad O-H

13.4. 2D/3D YAPI TAHMİNİ VE FORMÜLLERİ

13.4.1. 2D Structure Generation (RDKit)

Endpoint: POST /api/rdkit/draw-2d

Process:
  1. SMILES parsing: Chem.MolFromSmiles(smiles)
  2. 2D coordinate generation: AllChem.Compute2DCoords(mol)
  3. SVG rendering: Draw.rdMolDraw2D.MolDraw2DSVG()
  4. Options:
     - Atom numbering (optional)

     - Custom size (width × height)

Algorithm:
  ```python
  mol = Chem.MolFromSmiles(smiles)

  drawer = Draw.rdMolDraw2D.MolDraw2DSVG(width, height)
  drawer.DrawMolecule(mol)
  svg = drawer.GetDrawingText()
  ```

13.4.2. 3D Structure Generation (ETKDG + Force Field)

Endpoint: POST /api/rdkit/sdf-to-3d

Process:
  1. 2D SDF parsing (stereochemistry preservation)
  2. Chiral center detection
  3. Macrocycle detection (rings > 8 atoms)
  4. ETKDG embedding:
     - Experimental Torsion Knowledge Distance Geometry
     - Multiple random seeds (5-10 attempts)
     - enforceChirality = True
  5. Force field optimization:
     - MMFF94 (preferred, drug-like molecules)
     - UFF (fallback)
  6. Energy minimization: 500 iterations
  7. Best conformer selection (lowest energy)

ETKDG Parameters:
  ```python
  params = AllChem.ETKDGv3()
  params.randomSeed = 42
  params.useRandomCoords = False
  params.enforceChirality = True
  params.numThreads = 0  # All CPU cores
  ```

Macrocycle Handling:
  ```python
  if has_macrocycle:
      params.useSmallRingTorsions = True
      params.useMacrocycleTorsions = True
  ```

Energy Optimization:
  ```python
  # MMFF94 (preferred)
  mmff_props = AllChem.MMFFGetMoleculeProperties(mol)
  ff = AllChem.MMFFGetMoleculeForceField(mol, mmff_props)
  ff.Minimize(maxIts=500)
  energy = ff.CalcEnergy()
  
  # UFF (fallback)
  AllChem.UFFOptimizeMolecule(mol, maxIters=500)
  ```

13.4.3. Stereochemistry Preservation

Mechanism:
  1. 2D SDF'den wedge/dash bond bilgisi okunur
  2. Chiral centers tespit edilir (before 3D)
  3. enforceChirality = True ile embedding
  4. After 3D: Chiral center count verification
  5. Mismatch warning if changed

13.4.4. 3D Coordinate Calculation Formulas

Distance Geometry:
  - ETKDG uses experimental torsion angle distributions
  - Realistic conformations from crystal structure database
  - Better than random coordinate generation

Force Field Energy:
  - MMFF94: E = E_bond + E_angle + E_torsion + E_vdW + E_electrostatic
  - UFF: Universal Force Field (simpler, faster)

13.5.2. Peak Validation

13.5.3. Solvent Peak Filtering

Function: filterSolventPeaks(peaks, solvent, tolerance=0.5)

Solvent Database:

  - DMSO: 39.52 ppm (septet)
  - Acetone: 29.84 ppm (septet), 206.26 ppm (C=O, singlet)
  - MeOD: 49.00 ppm (septet)

  2. Return: { moleculePeaks, solventPeaks }

13.5.4. Formula Estimation from 13C

Function: estimateFormulaFrom13C(peaks)

Algorithm:
  1. Filter solvent peaks
  2. Count carbons: carbonCount = moleculePeaks.length
  3. Analyze shift distribution:
     - Aliphatic (<50 ppm): sp³ carbons
     - Heteroatom-substituted (50-100 ppm): C-O, C-N
     - Unsaturated (100-160 ppm): aromatic, alkene
     - Carbonyl (160-220 ppm): C=O
  4. Estimate heteroatoms:
     - Oxygen: heteroatom-substituted > 0 OR carbonyl > 0
     - Nitrogen: heteroatom-substituted > carbonyl
     - Aromatic: unsaturated > 3 (benzene ring)
  5. Estimate hydrogens:
     - Aromatic: ~1 H per C
     - Aliphatic: ~2 H per C
  6. Build formula: C{carbonCount}H{estimatedH}O{oxygenCount}N{nitrogenCount}

Confidence: 0.4-0.6 (low, rough estimation)

13.6.3. FTIR Prediction from SMILES

Function: predictFTIR(smiles: string)

Location: lib/spectromind/ir_engine/ftirEngine.ts

Pipeline:
  1. Parse SMILES → MolecularGraph
  2. Assign hybridization:
     - sp³: ~2900 cm⁻¹ (C-H)
     - sp²: ~3050 cm⁻¹ (aromatic C-H)
     - sp: ~3300 cm⁻¹ (alkyne C-H)
  3. Detect symmetry:
     - Equivalent atoms
     - Symmetry groups
  4. Calculate normal modes:
     - Hooke's Law: ν = (1/2πc) × √(k/μ)
     - Force constants (k)
     - Reduced mass (μ)
  5. Validate spectrum:
     - Standard regions check
     - C=O intensity check
     - O-H broadening warning
     - Peak count sanity check

13.6.4. Normal Mode Calculation

Function: calculateNormalModes(graph: MolecularGraph)

Location: lib/spectromind/ir_engine/normalModeSolver.ts

Force Constants (Base Values):
  - C-H sp³: 500 N/m → ~2900 cm⁻¹
  - C-H sp²: 550 N/m → ~3050 cm⁻¹
  - C-H sp: 600 N/m → ~3300 cm⁻¹
  - O-H: 750 N/m → ~3300-3600 cm⁻¹
  - C=O: 1200 N/m → ~1700-1750 cm⁻¹
  - C=C: 950 N/m → ~1620-1680 cm⁻¹
  - C≡C: 1600 N/m → ~2100-2260 cm⁻¹

Corrections:
  1. Conjugation: -20 to -60 N/m
  2. Ring strain: +20 to +50 N/m
  3. Hydrogen bonding: -50 to -100 N/m
  4. Electron-withdrawing: +20 N/m
  5. Anharmonicity: ν_real = ν_harmonic × (1 - χₑ × ν/10000)

A. Mimari Değişimi: Persistent Microservice

Yapı:

14.2.2. Önerilen Çözümler

A. GNN (Graph Neural Networks) Entegrasyonu

Neden Gerekli:
  - LLM molekülü "metin" olarak okur
  - GNN molekülü "topolojik harita" olarak işler
  - Chemical shift, atomun yerel elektronik çevresine bağlıdır
  - GNN, bu çevreyi atomdan atoma bilgi taşıyarak öğrenir

Veri Yapısı: Molekülü Grafa Dönüştürme

Düğümler (Nodes - V): Atom Özellik Vektörü
  - Atom Türü: (One-hot encoding: C, N, O, F...)
  - Hibritleşme: (sp, sp², sp³)
  - Aromatiklik: (True/False)
  - Formal Yük: (-1, 0, +1)
  - Bağlı Hidrojen Sayısı: (0, 1, 2, 3)
  - Kiralite: (R, S veya Yok)
  - Halka Durumu: (Halka içinde mi, boyutu ne?)

Kenarlar (Edges - E): Bağ Özellik Vektörü
  - Bağ Türü: (Tekli, Çiftli, Üçlü, Aromatik)
  - Konjugasyon: (Konjuge sistemin parçası mı?)
  - Stereokimya: (Cis/Trans, E/Z)
  - Halka Bağı: (Bağ bir halkanın parçası mı?)

Model Mimarisi: MPNN (Message Passing Neural Network)

Önerilen: ChemProp (Directed Message Passing Neural Network) veya SchNet

İşleyiş:
  A. Mesajlaşma Aşaması (K adım, genelde 3-6 katman):
     - Adım t=0: Atom sadece kendi özelliklerini bilir
     - Adım t=1: Atom, komşularından mesaj alır
     - Adım t=2: Atom, 2 bağ ötedeki grupları da "hisseder"
  
  B. Okuma Aşaması:
     - Her atomun nihai "Embedding" vektörü oluşur
     - Feed-Forward Neural Network (FFN) katmanına sokulur
     - Çıktı: PPM (Chemical Shift)

Matematiksel Formül:
  hv⁽ᵏ⁾ = UPDATE(hv⁽ᵏ⁻¹⁾, AGGREGATE({hu⁽ᵏ⁻¹⁾, ∀u ∈ N(v)}))

Eğitim Stratejisi:
  - Veri: 40.000+ deneysel spektrum (NMRShiftDB2)
  - Transfer Learning: Önce DFT verileri, sonra deneysel veriler
  - Loss Function: RMSE (Root Mean Square Error)

LLM ile Entegrasyon:
  1. GNN Servisi (FastAPI):
     - RDKit ile molekül grafı oluşturulur
     - Eğitilmiş ChemProp modeli çalıştırılır
     - Çıktı: Atom bazlı chemical shift tahminleri
  
  2. LLM Katmanı (Yorumlayıcı):
     - GNN çıktıları LLM'e prompt olarak gönderilir
     - LLM, sayısal sonuçları kullanıcıya açıklar
     - Reasoning ve assignment yapar

Teknoloji: PostgreSQL + pgvector

Veri Dönüşümü: Embedding (Gömme)

  - Semantik benzerlik: "Keton" ve "Karbonil" yakın vektörler

B. Spektral Embedding (NMR Parmak İzi):
  - Yöntem: Binning (0-12 ppm → 1200 parça)
  - CNN tabanlı kodlayıcılar
  - Benzer spektrumlar yakın vektörler

C. Yapısal Embedding (Moleküller):
  - Morgan Fingerprints algoritması
  - 1024 veya 2048 bitlik vektörler

Depolama:
  - PostgreSQL + pgvector eklentisi
  - HNSW (Hierarchical Navigable Small World) indeksleme
  - Milisaniyeler içinde nearest neighbor arama

Kullanım Senaryoları:
  1. Spektral Shazam:
     - Kullanıcı spektrumu yükler
     - Vektör DB'de benzer spektrumlar aranır
     - %98 benzerlik → Doğru molekül bulunur
  
  2. RAG ile Literatür Sohbeti:
     - Kullanıcı sorusu vektöre çevrilir
     - En alakalı 3 makale parçası bulunur
     - LLM'e context olarak gönderilir
     - Halüsinasyon engellenir

C. Self-Correction Loop (Oto-Düzeltme Döngüsü)

Mimari: Agentic Workflow (Ajan Tabanlı İş Akışı)

Ajanlar:
  1. Generator Agent (Sentezleyici):
     - Görev: Spektral veriye bakarak moleküler yapı önermek
     - Teknoloji: LLM (GPT-4o) + RAG
     - Çıktı: SMILES kodu
  
  2. Simulator Agent (Simülatör):
     - Görev: Önerilen yapının teorik spektrumunu hesaplamak
     - Teknoloji: GNN (ChemProp) veya RDKit HOSE
     - Çıktı: Teorik pik listesi
  
  3. Evaluator Agent (Değerlendirici):
     - Görev: Gerçek veri (Y_real) ile teorik veri (Y_pred) karşılaştırmak
     - Algoritma: Peak Matching (Hungarian Algorithm)
     - Hata: RMSD = √ [ (1/N) * ∑ (δ_real,i - δ_pred,i)² ]
  
  4. Critic Agent (Eleştirmen):
     - Görev: RMSD değerine göre karar vermek
     - Durum A (RMSD < 0.1): "Mükemmel, sonucu göster"
     - Durum B (RMSD > 0.5): "Hatalı, döngüyü tekrar başlat"
     - Feedback: Yapılandırılmış hata raporu Generator'a gönderilir

Teknoloji Stack:
  - Orchestrator: LangGraph veya AutoGPT
  - Simulator: Python + RDKit veya GNN (ChemProp)
  - Math Engine: SciPy (scipy.optimize.linear_sum_assignment)
  - Limit: MAX_RETRIES = 5

14.3. SPEKTROSKOPİ VE ALGORİTMALAR GELİŞTİRMELERİ

14.3.1. Mass Spectrometry (MS) Modülü

Mimari:
  - Bağımsız Python mikroservisi
  - Yüksek hacimli ham veri işleme

Kütüphaneler:
  - pyopenms veya pymzml: .mzML, .raw format okuma
  - SciPy, NumPy: Sinyal işleme, peak picking, FFT
  - RDKit: Moleküler ağırlık, izotop desenleri
  - CFM-ID: Competitive Fragmentation Modeling (Docker)

Pipeline (4 Aşama):

A. Ham Veri İşleme:
  - Baseline Correction: Top-hat filter veya Asymmetric Least Squares
  - Peak Picking: Local maxima tespiti
  - Noise Threshold: S/N < 3 olan pikler atılır

B. Moleküler İyon (M+) ve Adduct Tespiti:
  Algoritma: Adduct Scorer
  Error_ppm = | ((MW_calc + Δ_adduct) - m/z_obs) / m/z_obs | × 10⁶
  
  Yaygın Adduct Değerleri:
    [M+H]+: +1.0078 Da
    [M+Na]+: +22.9897 Da
    [M+K]+: +38.9637 Da
    [M+NH4]+: +18.0343 Da

C. İzotop Deseni Analizi:
  Teorik Simülasyon (Mercury Algoritması):
    P(k) = C(x, k) × (1.1%)ᵏ × (98.9%)⁽ˣ⁻ᵏ⁾
  
  Karşılaştırma:
    Score_iso = (v_theo • v_obs) / (||v_theo|| × ||v_obs||)
    Score_iso > 0.95 → Elementel formül doğrulanır

D. In-Silico Fragmentation:
  Yöntem: CFM-ID (Competitive Fragmentation Modeling)
  - Molekül grafa çevrilir
  - Bağ kırılma olasılıkları: P_cleave ∝ exp( -E_bond / (k × T_eff) )
  - Sanal spektrum oluşturulur
  - Gerçek ve sanal pikler Jaccard Benzerliği ile eşleştirilir

14.3.3. QM (Quantum Mechanical) Hesaplama Modülü

Strateji: Computational Funnel (3 Katmanlı)

Katman 1: Önbellek (Milisaniye)
  - QCArchive API sorgusu
  - SpectroMind Redis Cache (InChIKey hash)

Katman 2: Yarı-Deneysel (Saniyeler)
  - GFN2-xTB (Geometry, Frequency, Noncovalent)
  - Geometri optimizasyonu

Katman 3: GIAO-DFT (Dakikalar/Saatler)
  - B3LYP/6-31G(d) veya mPW1PW91/6-311+G(2d,p)
  - NMR Shielding hesaplaması

Matematiksel Temel:

Shielding Tensörü:
  σ_iso = (1/3) × Tr(σ) = (1/3) × (σ_xx + σ_yy + σ_zz)

Kimyasal Kayma:
  δ_sample = (σ_ref - σ_sample) / (1 - σ_ref) ≈ σ_ref - σ_sample

Lineer Ölçekleme:
  δ_final = (Slope × δ_calc) + Intercept
  Örn. 1H NMR (B3LYP/6-31G*): Slope = -1.05, Intercept = 31.8

Konformasyonel Tarama:
  Boltzmann Ağırlık:
    P_i = exp( -E_i / (k_B × T) ) / Σ exp( -E_j / (k_B × T) )
  
  Nihai Shift:
    δ_obs = Σ (P_i × δ_i)

Implementation:
  - Araç: CREST veya RDKit ETKDGv3
  - QM Motor: ORCA / NWChem (Docker)
  - Task Queue: Celery + Redis
  - Output Parsing: Regex ile ORCA .out dosyası

14.1. MS (KÜTLE SPEKTROMETRİSİ) TAHMİN MODÜLÜ

Genel Bakış:
  MS modülü, moleküllerin gaz fazındaki parçalanma davranışlarını simüle ederek
  teorik spektrum üretir. Kombinatoryal Fragmantasyon ve Bağ Ayrışma Enerjisi
  (BDE) temelli olasılıksal algoritma kullanır.

Matematiksel Model:
  A. Bağ Kopma Olasılığı (P_cleave):
     P_cleave(i) = A · e^(-E_bond(i) / (k · T_eff))
     
     - E_bond(i): Bağın ayrışma enerjisi (kcal/mol)
     - T_eff: Efektif sıcaklık (MS cihazındaki çarpışma enerjisi)
     - k: Boltzmann sabiti
  
  B. Fragman Şiddeti (Intensity):
     I_m/z = I_parent × P_cleave × S_ion
     
     - S_ion: İyonizasyon kararlılığı

Algoritma: Recursive Fragmentation Tree
  - Kök Düğüm: Ana molekül (Precursor Ion)
  - Dallanma: Tüm kırılabilir bağları tespit et
  - Kesme: Her bağı sanal olarak kes ve iki yeni fragman oluştur
  - Rekürsiyon: Oluşan fragmanları tekrar parçala (depth_limit = 2)
  - Sonlandırma: Fragmanlar çok küçükse veya olasılık eşiğinin altındaysa dur

Tanısal İyonlar (Diagnostic Ions):
  - Tropylium İyonu (C₇H₇⁺) | m/z 91: Benzil grubu (Ar-CH2-) varlığı
  - Iminium İyonları (R₂C=N⁺R₂): m/z 30, 44, 58 - Amin bileşikleri
  - McLafferty Düzenlenmesi: m/z 58 (keton), 74 (ester), 60 (asit)
  - Acylium İyonu (R-C≡O⁺): m/z 43, 57, 105
  - Oxonium İyonları (R-O⁺=CH₂): m/z 31, 45, 59

Dosya Yapısı:
  - services/ms-service/ms_predictor.py: Ana MS prediction engine
  - services/ms-service/main.py: Flask API servisi
  - lib/services/v2/MSService.ts: TypeScript service wrapper

14.2. 3D KONFORMER ÜRETİMİ VE BOLTZMANN AĞIRLIKLANDIRMA

Genel Bakış:
  Moleküller oda sıcaklığında tek bir "donuk" halde durmazlar. Enerji yüzeyinde
  sürekli hareket eder ve farklı şekillere (konformerlere) girerler. Bu modül,
  bu konformerleri üretir ve Boltzmann dağılımına göre ağırlıklandırır.

Matematiksel Model:
  A. Konformer Üretimi (ETKDGv3):
     - RDKit'in ETKDGv3 algoritması kullanılır
     - Cambridge Yapısal Veritabanı'ndan (CSD) öğrenilen torsion açıları
     - 50-100 adet rastgele 3D konformer üretilir
  
  B. Enerji Minimizasyonu (MMFF94):
     - MMFF94 (Merck Molecular Force Field) kuvvet alanı
     - Sterik çatışmaları giderir
  
  C. Boltzmann Ağırlıklandırma:
     P_i = e^(-(E_i - E_min) / RT) / Z
     
     - P_i: i. konformerin popülasyon yüzdesi
     - E_i: i. konformerin enerjisi (kcal/mol)
     - E_min: En düşük enerjili konformerin enerjisi
     - R: Gaz sabiti (0.001987 kcal/mol·K)
     - T: Sıcaklık (298 K - Oda sıcaklığı)
     - Z: Bölüşüm fonksiyonu (Tüm olasılıkların toplamı)
  
  D. Karplus Eşitliği (J-Coupling):
     J = 7 - 1.0 cos(φ) + 5.0 cos(2φ)
     
     - φ: Dihedral açı (H-C-C-H)
     - J: Vicinal coupling sabiti (Hz)

Algoritma Akışı:
  1. Input: 2D SMILES kodu
  2. Embed: 50-100 adet rastgele 3D konformer üretilir (ETKDGv3)
  3. Optimize: Her konformer MMFF94 ile optimize edilir
  4. Energy Pruning: Çok yüksek enerjili veya birbirinin aynısı (RMSD < 0.5 Å)
     olan konformerler elenir
  5. Weighting: Kalan konformerlerin Boltzmann ağırlıkları hesaplanır
  6. Analysis: Her konformer için Dihedral Açılar (H-C-C-H) ölçülür ve
     ağırlıklı ortalaması alınır

Dosya Yapısı:
  - services/conformer-service/conformer_engine.py: Ana conformer engine
  - services/conformer-service/main.py: Flask API servisi
  - lib/services/v2/ConformerService.ts: TypeScript service wrapper
  - app/api/v2/conformer-analysis/route.ts: Next.js API endpoint
  - components/molecules/ConformerViewer.tsx: 3D konformer görselleştirme

API Endpoint:

14.3. KUANTUM MEKANİKSEL (QM/DFT) DOĞRULAMA KATMANI

Genel Bakış:

  modülüdür. Empirik kurallar ve AI modelleri çalışmadığında, egzotik moleküller,
  gergin halkalar veya sterik olarak engellenmiş yapılar için fiziksel
  hesaplamalar yapar.

Matematiksel Model:
  A. Geometri Optimizasyonu (GFN2-xTB):
     - Semi-empirical quantum mechanical method
     - DFT'ye göre 1000 kat daha hızlı
     - Geometri konusunda DFT kadar hassas
  
  B. GIAO NMR Hesaplaması:
     - GIAO (Gauge-Including Atomic Orbitals): Manyetik alan altında
       elektronların çekirdeği ne kadar perdelediğini hesaplar
     - Shielding tensor (σ) hesaplama
     - Orijin noktasından bağımsız sonuçlar
  
  C. Shielding'den Shift'e Dönüşüm:
     δ_hesap = σ_ref - σ_numune
     
     - σ_ref: TMS (Tetrametilsilan) kalkanlama değeri
     - σ_numune: Hesaplanan molekülün kalkanlama değeri
  
  D. Lineer Ölçekleme:
     δ_final = (Intercept - σ_calc) / Slope
     
     - Sistematik hatayı düzeltir

Referans Değerleri:

  ────────────────────────────────

  C          185.4 ppm

  kavramsal arama yapar.

Vektörleştirme Stratejileri:
  A. Yapısal Embedding (Molecular Fingerprints):
     - Morgan Fingerprints (ECFP4)
     - Her atomun çevresini (yarıçap 2-3 bağ) tarar
     - 2048 uzunluğunda bit vektörü
     - Sonuç: Aspirin ve Salisilik Asit'in vektörleri uzayda birbirine çok yakındır

     - 0-12 ppm aralığı 1024 parçaya bölünür
     - Her parçadaki pik şiddeti o vektörün değerini oluşturur
     - Gaussian yayılımı ile fuzziness (piklerin biraz kaymasını tolere eder)
  
  C. Metin Embedding (Semantic Text):
     - Model: all-MiniLM-L6-v2 (Sentence Transformers)
     - Literatür taraması için makale özetleri vektöre çevrilir
     - Sonuç: "Anti-kanser" sorgusu ile "Sitotoksik ajan" içeren makale eşleşir
  
  D. Benzerlik Metriği (Cosine Similarity):
     Similarity = cos(θ) = (A · B) / (||A|| ||B||)

Hybrid Search:
  Text + Yapı + Spektrum benzerliklerini ağırlıklandırarak arar:
  scores = (text_similarity × weight_text) +

14.5. CLIENT-SIDE FID İŞLEME

Genel Bakış:
  Sunucu maliyetlerini sıfıra indiren ve veri gizliliğini %100 sağlayan
  devrimsel bir adımdır. 100 MB veya 1 GB boyutundaki ham NMR verisi (FID)
  internete yüklenmez. Bunun yerine, Python'un bilimsel kütüphaneleri (NumPy,
  SciPy) kullanıcının tarayıcısına indirilir (WASM) ve işlem kullanıcının kendi
  CPU/RAM gücüyle yapılır.

Matematiksel Temel:
  A. Pencereleme (Apodization / Windowing):
     S'(t) = S(t) × e^(-LB · t)
     
     - LB (Line Broadening): Genişletme faktörü (Genelde 0.3 Hz)
  
  B. Fourier Dönüşümü (FFT):
     S(f) = ∫(-∞ to ∞) S(t) e^(-i 2πft) dt
     
     - Cooley-Tukey algoritması kullanılır
  
  C. Faz Düzeltme (Phase Correction):
     S_new(ω) = S_old(ω) × e^(i(φ₀ + φ₁·ω))
     
     - φ₀ (Zero Order): Tüm spektrumu aynı açıda döndürür
     - φ₁ (First Order): Frekansa bağlı (pivot noktasına göre) döndürür

Mimari: Web Worker ve Pyodide
  - Main Thread (UI): Kullanıcı dosyayı seçer
  - Bridge: Dosya ArrayBuffer (binary) olarak Worker'a gönderilir
  - Worker Thread (Pyodide):
    * Sanal Dosya Sistemi (MEMFS) oluşturulur
    * Python scripti çalışır (FFT, Phasing)
    * Sonuç (JSON: x, y dizileri) UI'ya geri döner

DSP Zinciri:
  1. Apodization (Exponential Multiplication)
  2. Zero Filling (Çözünürlük Artırma)
  3. Fast Fourier Transform (FFT)
  4. Phase Correction (Zero-order + First-order)
  5. PPM Skalasını Oluştur
  6. Downsampling (64k → 4k nokta, Chart.js performansı için)

Dosya Yapısı:
  - public/pyodide/browser_nmr_processor.py: Python NMR processor (Pyodide)
  - public/pyodide/fid_worker.js: Web Worker (Pyodide + Python modülü)
  - lib/utils/v2/clientProcessing.ts: TypeScript client processing utilities
  - hooks/useClientFIDProcessing.ts: React hook
  - components/fid/FIDProcessorV2.tsx: FID processor UI component

Özellikler:
  - Bruker FID format desteği (Binary FID + ACQUS parsing)
  - Real-time faz ayarı (Slider ile anlık düzeltme)
  - Web Worker (UI donmadan işlem)
  - Veri gizliliği (FID verisi hiçbir zaman sunucuya gönderilmez)
  - Sunucu maliyeti: Sıfır (tüm işlem client-side)

Kullanım:
  Component kullanımı:
  <FIDProcessorV2 />

  Programmatic API:
  import { processFID } from '@/lib/utils/v2/clientProcessing';
  
  const result = await processFID(
    fidArrayBuffer,
    acqusContent,
    {
      phaseCorrection: { ph0: 0, ph1: 0 },
      apodization: 'exponential',
      apodizationParam: 0.3
    }
  );

Performans:
  - İlk Yükleme: ~5-10 saniye (Pyodide indirme)
  - FID İşleme: ~1-3 saniye (dosya boyutuna bağlı)
  - Real-time Faz: ~100ms (debounced)

14.6. ULTRATHINK KAPSAMLI TEORİK SPEKTRUM TAHMİN MOTORU

Genel Bakış:
  UltraThink, ULTRATHINK dokümanındaki tüm 150 temel prensip, 225 1H NMR parametresi,
  25 13C NMR birimi, 25 FTIR birimi ve 250 additivity kuralını içeren kapsamlı bir
  teorik spektrum tahmin motorudur. 2D molekül yapısından (SMILES) başlayarak tüm
  spektrumları (1H NMR, 13C NMR, FTIR) fiziksel/kimyasal kurallara göre tahmin eder.

Bölüm 1: Temel Prensipler ve Moleküler Hazırlık (150 Parametre)
  - Atom numarası, kütle numarası, çekirdek spini
  - Jiromanyetik oran, Larmor frekansı
  - Doymamışlık derecesi (DoB) hesabı: DoB = C - H/2 + N/2 + 1
  - Hibritleşme ve s-karakteri analizi (sp, sp2, sp3)
  - Simetri ve eşdeğerlik tespiti (Morgan algoritması)
  - Moleküler graf ve topolojik analiz

Bölüm 2: 1H NMR Master Algoritma (225 Parametre)
  - Shoolery Kuralı: Metilen (X-CH2-Y) için δ = 0.23 + σ_X + σ_Y
  - Tobey-Simon Kuralı: Olefinik protonlar için δ = 5.25 + Z_gem + Z_cis + Z_trans
  - Curphy-Morrison Kuralı: Aromatik protonlar için δ = 7.27 + Σ(S_ortho + S_meta + S_para)
  - Karplus Eşitliği: 3J = A + B·cos(φ) + C·cos²(φ) (dihedral açı bağımlılığı)
  - Multiplet ağacı (splitting tree) oluşturma
  - İkinci derece spin sistemleri (AB, AMX, AA'BB')

Bölüm 3: 13C NMR Tahmin (25 Birim)
  - Grant-Paul Denklemi: δ_C = -2.3 + 9.1α + 9.4β - 2.5γ + 0.3δ + Σ(Sterik)
  - Sterik düzeltme faktörleri (1°(3°), 1°(4°), 2°(3°), vb.)
  - Gamma-gauche etkisi (-5 ppm)
  - Aromatik 13C shift tahmini (128.5 ppm base)
  - Karbonil grupları (keton: 195 ppm, aldehit: 190 ppm, asit: 175 ppm, ester: 165 ppm, amid: 160 ppm)

Bölüm 4: FTIR Tahmin (25 Birim)
  - Hooke Yasası: ν = (1 / 2πc) * √(k / μ)
  - Bağ kuvvet sabiti (k) hiyerarşisi: C≡C (15) > C=C (10) > C-C (5) mdyn/Å
  - İndirgenmiş kütle (μ) hesabı: μ = (m1*m2)/(m1+m2)
  - Fonksiyonel grup bölgeleri (O-H: 3300, C=O: 1715, C-H: 2900 cm⁻¹)
  - Konjugasyon etkisi: ν_yeni = ν_taban - 30 cm⁻¹
  - Halka gerginliği etkisi (5'li: +30, 4'lü: +65 cm⁻¹)

Bölüm 5: Additivity Kuralları (250 Lookup Table)
  - Shoolery sabitleri (50+ grup: -Cl: 2.53, -OH: 2.56, -NO2: 3.36, vb.)
  - Curphy-Morrison sabitleri (16+ grup: -CH3, -NO2, -OH, -OMe, vb.)
  - Tobey-Simon sabitleri (15+ grup: -R, -Ph, -OMe, -COOR, vb.)
  - Grant-Paul parametreleri (α: 9.1, β: 9.4, γ: -2.5, δ: 0.3)
  - Sterik düzeltme faktörleri
  - Aromatik 13C sabitleri
  - Karbonil IR shift'leri

Bölüm 6: Bütünleşik Değerlendirme ve Çapraz Doğrulama
  - IR ↔ NMR ↔ 13C tutarlılık kontrolleri
  - Karbonil consistency: IR'da C=O varsa 13C'de 160-220 ppm olmalı
  - Aromatik consistency: DoB≥4 ise IR, H1, C13'te aromatik sinyaller olmalı
  - Entegrasyon doğrulama: Toplam H integration = moleküldeki H sayısı
  - Simetri/İntegral uyumu

Bölüm 8: Heteroatomlar (F, P, D, Si)
  - 19F (Flor) eşleşme sabitleri: 1J_CF (240-280 Hz), 2J_CF (20-50 Hz)
  - 31P (Fosfor) eşleşme sabitleri: 1J_PC (100-200 Hz), 2J_PH (10-20 Hz)
  - 2H (Döteryum) solvent pikleri: CDCl3 (77.16 ppm, triplet), DMSO-d6 (39.52 ppm, septet)
  - 29Si uyduları (TMS'de)

16.1. MOLEKULEPIPELINESERVICE v2.0 (SINGLE SOURCE OF TRUTH)

Dosya: lib/pipeline/MoleculePipelineService.ts
Sınıf: MoleculePipelineService (Singleton)

Amaç: Molekül işleme pipeline'ının tek merkez orchestrator'ü. Tüm aşamaları
deterministik sırayla yönetir ve "Single Source of Truth" prensibini uygular.

Pipeline Aşamaları:
1. Identity Resolution (resolveIdentity)
   - CID, molekül adı veya IUPAC'dan kimlik belirleme
   - PubChem API entegrasyonu
   - Formula doğrulama

2. Structure Resolution (resolveStructure)
   - SMILES çözümleme (PubChem, OPSIN)
   - Canonical vs Isomeric SMILES ayrımı
   - InChI ve InChIKey hesaplama
   - Stereo status belirleme ("full" | "partial" | "none")

3. Normalization & Validation (normalizeAndValidate)
   - Formula karşılaştırması
   - SMILES doğrulama
   - InChIKey format kontrolü
   - Warning sistemi (FORMULA_MISMATCH, STEREO_MISSING, vb.)

4. Graph Building (buildGraph)
   - Primary: RDKit API (/api/rdkit/parse-smiles)
     * 2D koordinatlar: rdDepictor.Compute2DCoords()
     * 3D koordinatlar: ETKDG + optimize
     * Atom sayıları hesaplama
     * Formül hesaplama (Hill sistemi)
     * DBE hesaplama
   - Fallback: JavaScript Parser (lib/utils/molecularStructure.ts)
     * Sınırlı destek (charge, stereo unsupported)
     * Düşük confidence (0.4)

5. NMR Prediction (predictNMR) - opsiyonel
   - Deterministic Model: Shoolery + Karplus
   - LLM Interpretation: GPT-4O (formül türetme YASAK)
   - Final Consensus: Model + LLM birleştirme

6. FID Comparison (optionalFIDCompare) - opsiyonel
   - Deneysel spektrum işleme
   - Teorik vs deneysel karşılaştırma

16.2. IDENTITY LOCK & FORMULA ENFORCEMENT

Problem: AI (LLM) spektrum analizinden yanlış formül türetiyor (örn: C10H10O).
Kullanıcı molekül seçtiyse (örn: Paclitaxel, C47H51NO14), AI'ın formül türetmesi
engellenmeli ve yalnızca seçilen molekülün formülü kullanılmalı.

Çözüm:
1. Pre-Processing (Prompt Level):
   - Kullanıcı molekül seçtiyse, prompt'a "CRITICAL IDENTITY LOCK" uyarısı eklenir
   - AI'a zorunlu formül verilir, formül türetme YASAK

2. Post-Processing (Response Override):
   - AI yanlış formül döndürürse, kullanıcı formülü ile override edilir
   - Confidence düşürülür (max 70%)
   - Warning eklenir (FORMULA_MISMATCH)

3. DBE Block Post-Processing:
   - AI'ın yazdığı DBE bloğu replace edilir
   - Kod tabanlı DBE hesaplama kullanılır (renderDBEBlock)

Dosya: lib/chem/formula.ts
- computeAtomCountsFromRDKitAtoms(): Atom sayılarını çıkarır
- formatHillFormula(): Hill sistemi formatlama (C, H, sonra alfabetik)
- computeDBE(): DBE hesaplama (C - H/2 - X/2 + N/2 + 1)
- validateFormula(): Formül karşılaştırması
- renderDBEBlock(): DBE analiz bloğu oluşturma

16.3. PEAK PARSING GUARDRAILS

Problem: FTIR cm⁻¹ değerleri (örn: 3300, 3500) ¹H NMR ppm olarak parse ediliyor.
Bu, yanlış formül türetmeye yol açıyor (örn: C27H24, C10H10O).

Çözüm: Strict Parsing Functions (lib/utils/peakParser.ts)

1. parseH1Peaks(text: string)
   - Format: δ 8.13 (d, 2H)
   - Guardrail: PPM aralığı -2 ile 15 arası
   - Reject: "δ 3300.00 (o, 1H)" → UNIT_MISMATCH warning

2. parseC13Peaks(text: string)
   - Format: δ 203.60 ppm (Cq)
   - Guardrail: PPM aralığı 0 ile 250 arası
   - Reject: "δ 300.00 ppm (Cq)" → OUT_OF_RANGE warning

3. parseFTIRBands(text: string)
   - Format: 3300 cm⁻¹ (50)
   - Guardrail: Wavenumber aralığı 400 ile 4000 cm⁻¹ arası
   - Reject: "100 cm⁻¹" → OUT_OF_RANGE warning

Warning Codes:
- "LINE_UNPARSEABLE": Format tanınmadı
- "MISSING_FIELDS": Numeric alanlar eksik
- "OUT_OF_RANGE": Değer aralık dışında
- "UNIT_MISMATCH": Birim uyumsuzluğu (örn: FTIR → NMR)

16.4. DBE CALCULATION (CODE-BASED)

Problem: DBE hesaplama AI'ya bırakılmış. AI yanlış formül türetince (C10H10O),
yanlış DBE hesaplıyor (DBE=7, doğrusu 6).

Çözüm: Code-based DBE Calculation (lib/chem/formula.ts)

Formül:
DBE = C - H/2 - X/2 + N/2 + 1
- C: Karbon sayısı
- H: Hidrojen sayısı
- X: Halojen toplamı (F + Cl + Br + I)
- N: Azot sayısı

Örnek:
- C47H51NO14: DBE = 47 - 51/2 - 0/2 + 1/2 + 1 = 23
- C10H10O: DBE = 10 - 10/2 - 0/2 + 0/2 + 1 = 6

DBE Post-Processing:
- AI'ın yazdığı DBE bloğu replace edilir
- Kod tabanlı DBE hesaplama kullanılır (renderDBEBlock)
- Effective formula: activeKnownMolecule?.formula ?? result.formula

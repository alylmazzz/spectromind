1.1. Temel Paradigma Değişimi

SpectroMind v1.0, SMILES analizi ve GPT-4 entegrasyonu ile sağlam bir temele 
sahiptir. Ancak 'Tekillik' (Singularity) seviyesi için NMR'ın doğası gereği 
olan 3D stereokimya ve kuantum mekaniksel etkilerin sisteme dahil edilmesi 
şarttır.

VİZYON:
SpectroMind v2.0, deterministik (fizik tabanlı) ve probabilistik (AI tabanlı) 
yaklaşımları birleştiren hibrit bir sistem olacaktır. Bu sistem, 2D yapı 
bilgisinden 3D konformer ensemble'ları üretecek, kuantum mekaniksel 
hesaplamalarla doğrulayacak ve grafik sinir ağları ile yüksek doğrulukta 
tahminler yapacaktır.

2.1. Modül 1: MS (Kütle Spektrometrisi) Tahmin Modülü

AÇIKLAMA:
Yapı tayininin eksik parçası olan Kütle Spektrometrisi sisteme eklenmelidir. 
Bu modül, molekülü sanal ortamda parçalayarak teorik MS spektrumu üretir.

İYİLEŞTİRME:
- In-Silico Fragmentation (Sanal Parçalanma) motoru
- Moleküler iyon (M+) tespiti
- Fragman pattern tahmini
- İzotopik dağılım hesaplama

TOOL:
- CFM-ID (Competitive Fragmentation Modeling)
- RDKit fragmentation
- MetFrag (alternatif)

İŞLEV:
1. Molekülü bağ enerjilerine göre parçalama
2. Teorik MS spektrumu üretme (m/z pikleri)
3. Moleküler iyon (M+) ve fragmanları belirleme
4. İzotopik dağılım hesaplama (M+1, M+2 pikleri)
5. Fragman assignment'ları

TEKNİK DETAYLAR:

API Endpoint: /api/ms-predict
Input: { smiles, ionization: 'EI' | 'ESI' | 'MALDI', energy: number }
Output: { peaks: [{ mz, intensity, assignment }], molecularIon: number }

Örnek Kullanım:
```typescript
POST /api/ms-predict
{
  "smiles": "CC(=O)Oc1ccccc1C(=O)O", // Aspirin
  "ionization": "EI",
  "energy": 70 // eV
}

Response:
{
  "molecularIon": 180.0423, // M+
  "peaks": [
    { "mz": 180.0423, "intensity": 100, "assignment": "M+" },
    { "mz": 138.0317, "intensity": 85, "assignment": "[M-CH2CO]+" },
    { "mz": 120.0211, "intensity": 45, "assignment": "[M-CH2CO-H2O]+" },
    { "mz": 92.0262, "intensity": 30, "assignment": "[C7H8]+" }
  ]
}
```

ENTEGRASYON:
- RDKit ile fragmentation
- CFM-ID ile competitive fragmentation modeling
- İzotopik dağılım: pyteomics veya mzlib

2.2. Modül 2: GNN (Graph Neural Network) Tabanlı Shift Tahmini

AÇIKLAMA:
LLM'lerin sayısal zayıflığını kapatmak için özelleşmiş grafik sinir ağları 
kullanılacaktır. Bu modül, atomik komşuluk matrislerini işleyerek yüksek 
doğrulukta kimyasal kayma tahmini yapar.

İYİLEŞTİRME:
- Kelime tabanlı tahmin yerine, atomik komşuluk matrislerini işleyen GNN
- <0.1 ppm hata payı ile tahmin
- Atomik çevre öğrenme

TOOL:
- ChemProp (MIT, özelleştirilebilir)
- DeepChem (TensorFlow tabanlı)
- SchNet (3D koordinat tabanlı)

İŞLEV:
1. SMILES string'ini moleküler grafa çevirme
2. Atomik komşuluk matrisi oluşturma
3. GNN ile her atomun elektronik çevresini öğrenme
4. Kimyasal kayma tahmini (δ ppm)
5. Confidence score hesaplama

TEKNİK DETAYLAR:

Model Mimarisi:
- Input: Moleküler graf (atomlar, bağlar, özellikler)
- GNN Layers: 3-5 katman (Graph Attention veya Message Passing)
- Output: Her atom için δ ppm tahmini

Özellik Vektörleri:
- Atom özellikleri: Elektronegatiflik, yarıçap, hibritleşme, formal charge
- Bağ özellikleri: Bağ tipi, bağ uzunluğu, aromatiklik
- Çevre özellikleri: Komşu atomlar, halka üyeliği, fonksiyonel grup

Eğitim Verisi:
- PubChem NMR veritabanı
- NIST Chemistry WebBook
- Özel veritabanları (SpectroMind library)

API Endpoint: /api/gnn-nmr-predict
Input: { smiles, atomIndices?: number[] }
Output: { predictions: [{ atomIndex, shift, confidence }] }

Örnek Kullanım:
```typescript
POST /api/gnn-nmr-predict
{
  "smiles": "CC(=O)Oc1ccccc1C(=O)O"
}

Response:
{
  "predictions": [
    { "atomIndex": 0, "shift": 2.31, "confidence": 0.95, "assignment": "CH3 (acetyl)" },
    { "atomIndex": 7, "shift": 7.45, "confidence": 0.92, "assignment": "Aromatic H" },
    { "atomIndex": 8, "shift": 7.62, "confidence": 0.91, "assignment": "Aromatic H" }
  ]
}
```

ENTEGRASYON:
- ChemProp model eğitimi ve inference
- Model checkpoint'leri S3'te saklanır
- Inference: Python API → Next.js API route

2.3. Modül 3: 3D Konformer Üretimi ve Boltzmann Ağırlıklandırma

AÇIKLAMA:
Stereokimyasal etkilerin (NOE, J-coupling) doğru hesaplanması için 3D 
konformer ensemble'ları üretilir ve Boltzmann ağırlıklandırma yapılır.

İYİLEŞTİRME:
- Tek bir 2D yapı yerine, molekülün uzaydaki olası 50-100 farklı duruşunu 
  (Konformer) üretip ortalamasını almak
- Cis/Trans izomerlerini, R/S kiral merkezleri ayırt etmek
- Karplus eşitliği için dihedral açıları hesaplamak

TOOL:
- RDKit ETKDGv3 algoritması (hızlı konformer üretimi)
- MMFF94 veya UFF force field (enerji hesaplama)
- Boltzmann ağırlıklandırma

İŞLEV:
1. SMILES'tan 3D koordinat üretimi
2. Konformer ensemble üretimi (50-100 konformer)
3. Enerji minimizasyonu (MMFF94/UFF)
4. Boltzmann ağırlıklandırma
5. Dihedral açı hesaplama (Karplus için)
6. Ağırlıklı ortalama kimyasal kayma

TEKNİK DETAYLAR:

Konformer Üretim Algoritması:
1. ETKDGv3 ile başlangıç konformerleri üret (50-100 adet)
2. MMFF94 ile enerji minimizasyonu
3. Enerji sıralaması
4. Boltzmann ağırlıklandırma: w_i = exp(-E_i/RT) / Σexp(-E_j/RT)
5. Ağırlıklı ortalama hesaplama

Dihedral Açı Hesaplama:
- Vicinal coupling (³J) için dihedral açı (φ)
- Karplus eşitliği: J = A·cos²(φ) + B·cos(φ) + C
- Her konformer için J değeri hesapla
- Ağırlıklı ortalama J değeri

API Endpoint: /api/conformer-analysis
Input: { smiles, numConformers?: number, temperature?: number }
Output: { conformers: [{ id, energy, weight, coordinates }], weightedAverage: number }

Örnek Kullanım:
```typescript
POST /api/conformer-analysis
{
  "smiles": "OC1=CC(=CC(O)=C1)/C=C/C2=CC=C(O)C=C2", // Trans-Resveratrol
  "numConformers": 50,
  "temperature": 298.15
}

Response:
{
  "conformers": [
    { "id": 0, "energy": -45.2, "weight": 0.15, "coordinates": [...] },
    { "id": 1, "energy": -44.8, "weight": 0.12, "coordinates": [...] }
  ],
  "weightedAverage": {
    "shift": 6.45,
    "coupling": 16.2 // Trans coupling
  }
}
```

ENTEGRASYON:
- RDKit Python API
- Konformer cache (S3 veya local storage)
- WebGL ile 3D görselleştirme (Three.js)

2.4. Modül 4: Kuantum Mekaniksel (DFT) Doğrulama Katmanı

AÇIKLAMA:
Egzotik ve gergin halkalı moleküller için fizik tabanlı doğrulama yapılır.

İYİLEŞTİRME:
- Şüpheli durumlarda fizik tabanlı hesaplama yapmak (Ab Initio)
- Hızlı geometri optimizasyonu
- Yaklaşık NMR shielding hesaplaması

TOOL:
- ASE (Atomic Simulation Environment) arayüzü
- xTB (Semi-empirical, hızlı)
- ORCA (DFT, yavaş ama doğru)
- Gaussian (alternatif)

İŞLEV:
1. Geometri optimizasyonu (xTB veya ORCA)
2. NMR shielding hesaplama (GIAO method)
3. Kimyasal kayma tahmini (TMS referansı)
4. Confidence score güncelleme

TEKNİK DETAYLAR:

Hesaplama Stratejisi:
- Küçük moleküller (<20 atom): ORCA DFT (B3LYP/6-31G*)
- Orta moleküller (20-50 atom): xTB semi-empirical
- Büyük moleküller (>50 atom): Sadece şüpheli durumlarda

NMR Shielding Hesaplama:
- GIAO (Gauge-Including Atomic Orbitals) method
- TMS referansı: σ_TMS = 31.9 ppm (¹H)
- Kimyasal kayma: δ = σ_TMS - σ_molecule

API Endpoint: /api/dft-verify
Input: { smiles, method?: 'xtb' | 'orca', level?: string }
Output: { shifts: [{ atomIndex, shift, method }], computationTime: number }

Örnek Kullanım:
```typescript
POST /api/dft-verify
{
  "smiles": "C1CCC2CCCCC2C1", // Bicyclic strained ring
  "method": "xtb"
}

Response:
{
  "shifts": [
    { "atomIndex": 0, "shift": 1.85, "method": "xTB" },
    { "atomIndex": 1, "shift": 1.92, "method": "xTB" }
  ],
  "computationTime": 12.5 // seconds
}
```

ENTEGRASYON:
- ASE Python API
- xTB binary (local veya Docker container)
- ORCA (HPC cluster veya cloud)
- Job queue (Celery veya AWS Batch)

2.5. Modül 5: Vektör Tabanlı 'Benzerlik' Arama (RAG)

AÇIKLAMA:
Kelime eşleşmesi yerine anlamsal ve yapısal arama yapılır.

İYİLEŞTİRME:
- Semantic Search & Substructure Search
- Spektrum verilerini ve molekül yapılarını vektöre çevirme
- 'Görüntü/Desen' araması (Örn: 'Aspirin benzeri yapılar')

TOOL:
- Pinecone (managed vector database)
- Milvus (self-hosted)
- pgvector (PostgreSQL extension)

İŞLEV:
1. Molekül yapılarını vektöre çevirme (molecular fingerprints)
2. Spektrum verilerini vektöre çevirme (peak pattern embeddings)
3. Vektör veritabanına kaydetme
4. Benzerlik araması (cosine similarity)
5. Substructure araması (SMARTS pattern)

TEKNİK DETAYLAR:

Vektör Embedding Stratejisi:

1. Molekül Embedding:
   - RDKit molecular fingerprints (Morgan, MACCS)
   - GNN node embeddings (ChemProp)
   - 3D shape descriptors

2. Spektrum Embedding:
   - Peak pattern → histogram (binning)
   - Fourier transform
   - Autoencoder embeddings

3. Hybrid Search:
   - Vektör arama (semantic similarity)
   - Substructure arama (SMARTS)
   - Metadata filtreleme (formül, fonksiyonel grup)

API Endpoint: /api/vector-search
Input: { query: { type: 'molecule' | 'spectrum', data: string }, topK?: number }
Output: { results: [{ molecule, similarity, spectrum }] }

Örnek Kullanım:
```typescript
POST /api/vector-search
{
  "query": {
    "type": "spectrum",
    "data": "7.2(m,5H), 4.6(s,2H), 2.1(br s,1H)" // Benzyl alcohol pattern
  },
  "topK": 10
}

Response:
{
  "results": [
    { "molecule": "Benzyl alcohol", "similarity": 0.95, "spectrum": "..." },
    { "molecule": "Phenethyl alcohol", "similarity": 0.87, "spectrum": "..." }
  ]
}
```

ENTEGRASYON:
- Pinecone API (veya Milvus)
- pgvector (PostgreSQL)
- Embedding pipeline (batch processing)

2.6. Modül 6: Tarayıcı Tabanlı (Client-Side) İşleme

AÇIKLAMA:
Sunucu yükünü azaltmak ve veri gizliliğini artırmak için client-side işleme.

İYİLEŞTİRME:
- WebAssembly tabanlı sinyal işleme
- GB'lık FID dosyalarını sunucuya yüklemeden tarayıcıda işleme

TOOL:
- Pyodide (Python in WebAssembly)
- WebAssembly (C/C++ compiled)
- Web Workers (parallel processing)

İŞLEV:
1. FID dosyasını tarayıcıda yükleme
2. FFT (Fast Fourier Transform) işleme
3. Faz ayarı (phase correction)
4. Baseline düzeltmesi
5. Peak picking
6. İşlenmiş spektrumu sunucuya gönderme (opsiyonel)

TEKNİK DETAYLAR:

WebAssembly Modülleri:
1. FFT Module (C/C++ compiled to WASM)
2. Signal Processing (numpy.js veya Pyodide)
3. Peak Picking (scipy.js veya custom WASM)

İşlem Akışı:
1. Kullanıcı FID dosyasını seçer (tarayıcıda)
2. Web Worker'da FFT işleme
3. Faz ayarı (interaktif slider)
4. Baseline düzeltme
5. Peak picking
6. Sonuçları göster (veya sunucuya gönder)

API: Client-Side Only (No Server Call)
Input: File (FID format)
Output: { peaks: [{ shift, intensity }], spectrum: Float32Array }

Örnek Kullanım:
```typescript
// Client-side (browser)
const fidFile = await fileInput.files[0].arrayBuffer();
const processed = await processFID(fidFile, {
  fftSize: 65536,
  phaseCorrection: { ph0: 0, ph1: 0 },
  baselineCorrection: true
});

console.log(processed.peaks); // [{ shift: 7.2, intensity: 100 }, ...]
```

ENTEGRASYON:
- Pyodide (Python runtime in browser)
- Web Workers (background processing)
- IndexedDB (local storage for large files)

3.4. API Tasarımı

RESTful API Endpoints:

POST /api/v2/predict
   Comprehensive prediction (all modules)
   Input: { smiles, options: { includeMS, includeDFT, ... } }
   Output: { nmr, ftir, ms, conformers, dft }

POST /api/v2/ms-predict
   MS spectrum prediction
   Input: { smiles, ionization, energy }
   Output: { peaks, molecularIon }

POST /api/v2/gnn-nmr-predict
   GNN-based NMR prediction
   Input: { smiles, atomIndices }
   Output: { predictions }

POST /api/v2/conformer-analysis
   Conformer generation and Boltzmann weighting
   Input: { smiles, numConformers, temperature }
   Output: { conformers, weightedAverage }

POST /api/v2/dft-verify
   DFT verification
   Input: { smiles, method, level }
   Output: { shifts, computationTime }

POST /api/v2/vector-search
   Vector similarity search
   Input: { query, topK }
   Output: { results }

GET /api/v2/health
   Health check
   Output: { status, services: { ... } }

7.1. Teknik Riskler

RİSK 1: GNN Model Eğitimi
   - Problem: Yeterli eğitim verisi yok
   - Çözüm: PubChem + NIST veritabanları, transfer learning

RİSK 2: DFT Hesaplama Süresi
   - Problem: ORCA çok yavaş (>30 dakika)
   - Çözüm: xTB kullan (hızlı), ORCA sadece kritik durumlarda

RİSK 3: WebAssembly Performansı
   - Problem: Pyodide yavaş olabilir
   - Çözüm: Native WASM modülleri (C/C++), Web Workers

7.2. Performans Riskleri

RİSK 1: Konformer Üretimi
   - Problem: 100 konformer >5 saniye
   - Çözüm: Paralel işleme, caching, lazy loading

RİSK 2: Vector Search Ölçeklenebilirliği
   - Problem: Büyük veritabanı yavaş
   - Çözüm: Indexing, sharding, CDN

RİSK 3: API Response Time
   - Problem: Çoklu modül çağrıları yavaş
   - Çözüm: Async processing, caching, CDN

7.3. Entegrasyon Riskleri

RİSK 1: Microservices Communication
   - Problem: Network latency, failures
   - Çözüm: Retry logic, circuit breaker, health checks

RİSK 2: Dependency Versions
   - Problem: Kütüphane uyumsuzlukları
   - Çözüm: Version pinning, Docker isolation

RİSK 3: Data Consistency
   - Problem: Cache invalidation
   - Çözüm: TTL, event-driven updates
